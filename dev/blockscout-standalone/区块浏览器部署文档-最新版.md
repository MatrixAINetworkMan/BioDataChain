# 区块浏览器（Blockscout）最新版部署文档

> 适用版本：**后端 optimism v11.2.0（自编译）+ 前端 v2.8.0（自编译）**
> 部署形态：独立机器部署（浏览器与链节点分机），通过远程 RPC 索引链数据
> 配套目录：`dev/blockscout-standalone/`
> 最后更新：2026-06-24
>
> 本文档面向部署/运维，照着做即可，不需要读源码。所有命令默认在
> `dev/blockscout-standalone/` 目录下执行（除非另有说明）。

---

## 0. 这是什么

一台只跑「区块浏览器」的机器，用来浏览链上区块 / 交易 / 地址 / 合约。
它**不出块、不存钱、不是链的一部分**；挂了不影响链运行，重装即可恢复（数据能从链重新索引）。
链节点（op-geth / op-node / op-batcher / L1）在**另一台机器**。

```
┌──────────────────────────┐      RPC (HTTP/WS/trace)      ┌──────────────────────────┐
│  链机器（不归本机管）       │ ◀───────────────────────────  │  本机：Blockscout 浏览器   │
│  op-geth  :9545 / :9546   │                              │  8 个 docker 容器          │
│  op-node / op-batcher     │      L1 RPC :8545           │  + nginx 反代 + HTTPS      │
│  L1 geth  :8545（或独立机） │ ◀───────────────────────────  │                            │
└──────────────────────────┘                              └──────────────────────────┘
        提供数据源                                              本机消费数据源
```

**本机 8 个容器**（一套 docker compose）：

| 容器 | 作用 | 挂了的后果 |
|------|------|-----------|
| `blockscout-backend` | 索引器 + API（核心） | 整站不更新、API 502 |
| `blockscout-frontend` | 网页界面 | 网页打不开 |
| `blockscout-stats` | 首页图表 | 「Daily transactions」为 0 |
| `blockscout-db` | 主库 Postgres | backend 起不来 |
| `blockscout-stats-db` | 图表库 Postgres | 图表服务起不来 |
| `blockscout-redis` | 缓存 | backend 起不来 |
| `blockscout-verifier` | 合约验证 | 验证功能失效（非核心） |
| `blockscout-sig-provider` | 函数签名解码 | 交易解码不全（非核心） |

## 1. 前置要求

### 1.1 本机（浏览器机器）
- Linux + Docker 20.10+ + `docker compose` v2
- 工具：
  ```bash
  sudo apt update && sudo apt install -y docker-compose-plugin jq gettext-base curl openssl
  ```
- 内存 ≥ 4G 运行（**自编译另需更多，见 §2**）；磁盘 ≥ 50G（索引数据随链增长，生产建议 1TB+ SSD）
- 一个解析到本机公网 IP 的域名（如 `scan.example.com`）+ HTTPS 证书

### 1.2 链机器必须对本机开放的端口
索引依赖**远程 RPC**，链机器需让本机可达：

| 用途 | 端口 | 说明 |
|------|------|------|
| L2 op-geth HTTP | `9545` | `eth_*`，且 **`--http.api` 必须含 `debug`**（internal txns / trace 要用） |
| L2 op-geth WS | `9546` | 实时索引（newHeads 订阅）必需 |
| L1 geth HTTP | `8545` | optimism 跨链索引（deposit / withdrawal / batch） |

> indexer 的 RPC **建议指向只读副本**，不要指主 sequencer（避免给出块节点加查询压力）。
> 安全：RPC 端口别对整个公网敞开（`debug_*` 可被滥用），用安全组只放行本机 IP 或带访问控制的 nginx。

## 2. 自编译镜像（最新版的关键，必读）

⚠️ **后端 optimism flavor 和前端新版都没有公开镜像，必须自己编译。**

- **后端**：Blockscout 自 v10 起停发公开 optimism 镜像，`ghcr.io/blockscout/blockscout-optimism`
  永久停在 **9.0.2**（10/11 全 404），新版只推私有仓库（外部拉不了）。而 optimism 是「编译期」chain
  type，通用 `blockscout` 镜像不能索引 OP 的 deposit/withdrawal/batch → 上 v11 只能从源码编译。
- **前端**：公开 `ghcr.io/blockscout/frontend` 永久停在 **v2.3.5**（`:latest` 也指它），v2.7/v2.8 只推私有
  仓库 → 要 v2.8.0（与 v11 后端最佳兼容）也得自编译。
- **stats / verifier / sig-provider**：flavor 无关的公开镜像，照常用官方 tag/digest。

### 2.1 编译后端 optimism v11.2.0
```bash
# 需要 docker + git；Elixir 编译较重：约 4GB+ 内存、15–30 分钟
cd /data
git clone --depth 1 --branch v11.2.0 https://github.com/blockscout/blockscout.git blockscout-src
cd blockscout-src
DOCKER_BUILDKIT=1 docker build -f docker/Dockerfile \
  --build-arg CHAIN_TYPE=optimism \
  --build-arg RELEASE_VERSION=11.2.0 \
  --build-arg BLOCKSCOUT_VERSION=v11.2.0 \
  -t blockscout-optimism:11.2.0-local .
# 校验
docker run --rm --entrypoint sh blockscout-optimism:11.2.0-local -c 'echo $RELEASE_VERSION'   # 期望 11.2.0
```

### 2.2 编译前端 v2.8.0
```bash
# 构建峰值 ~8GB 内存（Dockerfile 写死 --max-old-space-size=8192），内存不足先加 swap：
#   sudo fallocate -l 8G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
cd /data
git clone --depth 1 --branch v2.8.0 https://github.com/blockscout/frontend frontend-src
cd frontend-src
docker build -f Dockerfile --build-arg GIT_TAG=v2.8.0 -t blockscout-frontend:2.8.0-local .
```

### 2.3 stats / verifier / sig-provider 取 digest（公开镜像）
```bash
ST=ghcr.io/blockscout/stats:latest               # 必须 ≥ v2.16.0（适配后端 v11 表结构）
VF=ghcr.io/blockscout/smart-contract-verifier:latest
SP=ghcr.io/blockscout/sig-provider:latest
for i in "$ST" "$VF" "$SP"; do docker pull "$i"; done
echo "BLOCKSCOUT_BACKEND_IMAGE=blockscout-optimism:11.2.0-local"
echo "BLOCKSCOUT_FRONTEND_IMAGE=blockscout-frontend:2.8.0-local"
echo "BLOCKSCOUT_STATS_IMAGE=$(docker inspect --format '{{index .RepoDigests 0}}' "$ST")"
echo "BLOCKSCOUT_VERIFIER_IMAGE=$(docker inspect --format '{{index .RepoDigests 0}}' "$VF")"
echo "BLOCKSCOUT_SIG_PROVIDER_IMAGE=$(docker inspect --format '{{index .RepoDigests 0}}' "$SP")"
```
把这 5 行填回 `.env` 的对应变量（后端/前端用本地自编译 tag，其余钉 digest 防 `:latest` 漂移）。

## 3. 部署

```bash
# 1. 拿代码（git clone 整个仓库，或只拷 dev/blockscout-standalone）
cd dev/blockscout-standalone

# 2. 品牌素材：assets/{logo.svg,icon.svg,logo512.png} 已随仓库自带；
#    9 件套 favicon 会在 install.sh 首次运行时自动用 dpokidov/imagemagick 生成（~60s + 首拉镜像 ~200MB）。
#    换品牌图：覆盖 assets/{logo.svg,icon.svg,logo512.png} 后跑 bash scripts/make-favicon.sh --force

# 3. 配置（把所有 REPLACE_ME 改成真实值，详见 §4）
cp .env.example .env
vim .env

# 4. 一键安装（自检连通性 → 渲染配置 → 生成 favicon → 拉/用镜像 → 起服务 → 等健康）
./install.sh

# 5. nginx 反代 + HTTPS
sudo cp nginx/blockscout.conf.example /etc/nginx/conf.d/<域名>.conf
sudo vim /etc/nginx/conf.d/<域名>.conf      # 改 server_name 和 ssl 证书路径
sudo nginx -t && sudo systemctl reload nginx
```

`install.sh` 是**幂等**的：改完 `.env` 重跑即可重新生效。首次启动 backend 要建表 + 重新索引，
**1–3 分钟**后首页才有数据，全量追上链头随链长短而定。

## 4. 配置项（`.env` 必填）

| 变量 | 含义 | 取值来源 |
|------|------|---------|
| `BLOCKSCOUT_PUBLIC_URL` | 浏览器对外域名 | 本机域名，如 `https://scan.example.com` |
| `L2_RPC_HTTP` / `L2_RPC_WS` / `L2_RPC_TRACE` | 链 RPC（索引用） | 链机器 op-geth 可达地址；HTTP/TRACE 通常同一地址 `:9545`，WS `:9546` |
| `L2_RPC_PUBLIC_URL` | 钱包用公网 RPC | **必须 HTTPS**，如 `https://dev.example.com/rpc` |
| `L1_RPC` | L1 RPC | L1 机器 geth 可达地址 `:8545` |
| `L2_CHAIN_ID` | 链 ID | 跟链一致（错了 install 会拦） |
| `OPTIMISM_PORTAL_PROXY` 等 4 个合约地址 | L1 合约地址 | 链机器 `cat workdir/shared/l1-addresses.env` |
| `BATCH_INBOX_ADDRESS` | batch inbox | 链机器 `jq .batch_inbox_address workdir/shared/rollup.json` |
| `BLOCKSCOUT_*_IMAGE`（5 个） | 镜像版本 | 见 §2.3 |
| `BLOCKSCOUT_SECRET_KEY_BASE` | 密钥 | 留空则 install 自动生成；生产可 `openssl rand -base64 64` |

> `.env` 含生产实际值与密钥，**勿外泄、勿入库**。`envs/*.tpl` 是模板，由 install 渲染成
> `envs/*.env`，**别手改渲染产物**（会被下次 install 覆盖）。

## 6. 已知坑位（v11.2.0 / v2.8.0 自编译，务必知道）

这些是本套版本实际踩过的坑，`install.sh` / 模板里已默认处理好，列出供排障参考。

### 6.1 「Internal txns」标签为空 ★最易踩

内部交易由后端**单独的索引器**抓，区块索引正常≠内部交易有。分两层排查：

**① 确认索引器实际开着** —— `docker-compose.yml` 里 backend 段的 `environment:` **优先级高于**
`env_file:`（即 `envs/backend.env`）。若 compose 里硬写了
`INDEXER_DISABLE_INTERNAL_TRANSACTIONS_FETCHER=true`，会盖掉 env_file，索引器实际是关的、全库 0 条。
```bash
# 看容器里「实际生效」的值，必须是 false
docker compose exec -T backend env | grep INTERNAL_TRANSACTIONS_FETCHER
# 排查三处定义，确认没有 =true
grep -rn 'INTERNAL_TRANSACTIONS_FETCHER' . 2>/dev/null
#   envs/backend.env.tpl / envs/backend.env 应为 =false；docker-compose.yml 不该出现这行
# 若 compose 里被写成 true，改回 false 后重建 backend：
sed -i 's/- INDEXER_DISABLE_INTERNAL_TRANSACTIONS_FETCHER=true/- INDEXER_DISABLE_INTERNAL_TRANSACTIONS_FETCHER=false/' docker-compose.yml
docker compose up -d backend
```
开启后**新块**自动抓；验证（隔一两分钟跑两次，应在涨）：
```bash
docker compose exec -T db psql -U blockscout -tAc "select count(*) from internal_transactions;"
```

**② 回填历史块**（索引器曾关过才需要）—— 关闭期间导入的块不会自动补，需重新入队：
```bash
# 先核对队列表列名（不同版本可能略有差异）
docker compose exec -T db psql -U blockscout -c "\d pending_block_operations"
# 把「有交易、但还没内部交易」的共识块批量入队（幂等，可重复跑）
docker compose exec -T db psql -U blockscout <<'SQL'
INSERT INTO pending_block_operations (block_hash, block_number, inserted_at, updated_at)
SELECT b.hash, b.number, now(), now()
FROM blocks b
WHERE b.consensus = true
  AND EXISTS     (SELECT 1 FROM transactions t           WHERE t.block_hash = b.hash)
  AND NOT EXISTS (SELECT 1 FROM internal_transactions it WHERE it.block_number = b.number)
  AND NOT EXISTS (SELECT 1 FROM pending_block_operations p WHERE p.block_hash = b.hash)
ON CONFLICT DO NOTHING;
SQL
# 进度：剩余应降、已入库应涨
docker compose exec -T db psql -U blockscout -tAc "select count(*) from pending_block_operations;"
docker compose exec -T db psql -U blockscout -tAc "select count(*) from internal_transactions;"
```
> 数据量大或图省事，测试环境也可直接 `docker compose down -v && ./install.sh` 全量重灌
> （索引器开着从创世重抓，内部交易自然齐全），代价是整条链重新同步。

> 日志里 `Indexer.Fetcher.OnDemand.FirstTrace terminating ... unknown field :block_hash` 是
> v11.2.0 自编译版「按需补 trace」旁路的已知 bug，只在打开未索引交易页时偶发，**不影响主索引器**，可忽略。

### 6.2 前端 v2.8.0 启动报 asset 下载失败
v2.8.0 的 entrypoint 会在**启动时**下载 `NEXT_PUBLIC_NETWORK_LOGO/ICON` 指向的 URL，下不到就硬 `exit 1`
（旧版只告警）。容器访问自己公网域名有 NAT 回环问题 → 必失败。
**对策（模板已配好）**：这两个变量用 `file:///app/public/assets/network/*.svg` 指向容器内挂载的本地文件，
让下载步骤变成本地 cp，不走网络。实际浏览器端 logo 始终从本地 `/assets/...` 伺服，与该变量值无关。

### 6.3 前端 v2.8.0 启动报 `Congruity check failed`
v2.7 起 `NEXT_PUBLIC_ROLLUP_L1_BASE_URL` 被移除，改用 `NEXT_PUBLIC_ROLLUP_PARENT_CHAIN`（JSON）。
还设旧变量会被 envs-validator 判失败 → 前端 exit 1。**模板已改用新变量**。

### 6.4 后端 v11 连 Postgres 报 `ssl not available`
v11+ 默认尝试 SSL 连库。非 SSL 的本地 Postgres 需设 `ECTO_SSL_MODE=disable`（**模板已设**）。

### 6.5 后端报 `eaddrnotavail`（临时端口耗尽）
高 TPS 下索引器对 L2 RPC 短连接过多耗尽临时端口。**docker-compose 已加 `sysctls`** 放宽端口范围 +
开启 tw_reuse 缓解。

## 7. 日常运维

```bash
# 状态 / 日志
docker compose ps                      # 8 容器应 Up/healthy
docker compose logs -f backend         # 索引器日志（最常看）
docker compose logs --tail=200 frontend stats
docker stats --no-stream               # 内存/CPU

# 起停 / 重启
docker compose up -d                   # 起 / 应用改动
docker compose restart backend         # 重启单个服务
docker compose down                    # 停（保留数据）
docker compose down -v                 # ⚠️ 停 + 删库（清索引，需重新同步整条链）

# 改配置后生效：改完 .env 或 envs/*.tpl 后重跑（幂等）
./install.sh
```

### 备份 / 恢复
```bash
# 备份主库（建议 crontab 每日凌晨 + 同步对象存储）
docker compose exec -T db pg_dump -U blockscout blockscout | gzip > backup-$(date +%F).sql.gz
# 恢复
gunzip -c backup-2026-06-01.sql.gz | docker compose exec -T db psql -U blockscout blockscout
docker compose restart backend
```
> 数据可从链重新索引，备份非强制；但全量重索引耗时随链增长，定期备份省恢复时间。

### 磁盘清理
```bash
docker system prune -f          # 清无用镜像/容器（不动卷，安全）
# 日志已限 20m×5/容器，一般无需手动清
```

## 8. 升级 / 换版本

- **同大版本换补丁**：改 `.env` 镜像版本 → `./install.sh`（backend 启动自动 `create_and_migrate()`）。
- **跨大版本（如 9.x → v11）**：官方要求 v11 须装在 v10.1 之上，无法直接迁移。测试环境推荐
  **greenfield 清库重装**：
  ```bash
  # 先按 §2 编好新镜像、§2.3 填好 .env 的 5 个镜像变量
  docker compose --env-file .env down -v     # ⚠️ 清空索引，整条链重新同步
  ./install.sh
  docker compose logs -f backend             # 看 v11 建表 + 重新索引
  ```
- 升级前务必备份（§7）。`install.sh` 的 pull 带 `--ignore-pull-failures`，本地自编译镜像不会因拉取失败中断。

## 9. 故障速查

| 症状 | 排查 / 处理 |
|------|-------------|
| 网页 502 / 打不开 | `docker compose ps`、`docker compose logs backend frontend`；`sudo nginx -t && systemctl reload nginx` |
| 区块号不涨 | 链 RPC 断：`docker compose logs backend \| grep -i rpc`；自检 `L2_RPC_HTTP/WS` 连通、`debug` 是否开 |
| 首页 Daily transactions 一直 0 | `docker compose logs stats`；确认 `/stats-api/` 反代通、stats 镜像 ≥ v2.16 |
| **Internal txns 标签空** | **见 §6.1**（先查索引器是否被 compose 覆盖关闭，再看是否需回填） |
| deposit/withdrawal 页空 | L1 索引失败：`docker compose logs backend \| grep -i optimism`；查 `L1_RPC` + 4 个合约地址 |
| 钱包「添加网络」报 RPC 无效 | `L2_RPC_PUBLIC_URL` 必须 HTTPS |
| 实时不刷新需手动 F5 | nginx 缺 WebSocket `map $http_upgrade ...`，或 backend `CHECK_ORIGIN` 拦了 Origin |
| 前端启动报 asset 下载失败 | 见 §6.2（logo/icon 用 `file://` 本地路径） |
| 前端启动报 `Congruity check failed` | 见 §6.3（删旧变量，用 `NEXT_PUBLIC_ROLLUP_PARENT_CHAIN`） |
| 后端报 `ssl not available` | 见 §6.4（`ECTO_SSL_MODE=disable`） |
| 后端报 `eaddrnotavail` | 见 §6.5（compose `sysctls`） |
| frontend 报 `mounting ".../favicon.ico" ... not a directory` | `assets/favicon/` 缺文件被 bind-mount 成伪目录：`docker compose stop frontend && docker compose rm -f frontend && bash scripts/make-favicon.sh --force && docker compose up -d frontend` |
